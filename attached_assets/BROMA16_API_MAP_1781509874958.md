# BROMA16 — ПОЛНАЯ КАРТА ВОЗМОЖНОСТЕЙ API

Base URL: `https://api-rod.broma16.ru/api`
Auth: JWT (X-Access-Token header)

---

## ПОЛНЫЙ СПИСОК ENDPOINTS (40+ штук)

### 1. АВТОРИЗАЦИЯ
| Метод | Endpoint | Назначение |
|-------|----------|-----------|
| POST | /auth/login | Вход → access_token + refresh_token |
| POST | /auth/refresh | Обновление access_token (когда 401) |
| POST | /auth/logout | Выход |

### 2. ПОЛЬЗОВАТЕЛЬ
| Метод | Endpoint | Назначение |
|-------|----------|-----------|
| GET | /user/ | Текущий пользователь + список аккаунтов (account_id!) |

### 3. СЛОВАРИ (кэшировать при старте)
| Метод | Endpoint | Назначение |
|-------|----------|-----------|
| GET | /dictionaries/genres?object_type=music | Жанры (id + название) |
| GET | /dictionaries/languages | Языки (id + название) |
| GET | /dictionaries/release-types?category=audio&language=ru | Типы релизов (Сингл=51, Альбом=2, EP, RBT=43, RT=42, TikTok=70) |
| GET | /dictionaries/outlets | Витрины/площадки (Spotify, Apple, Yandex, VK, Zvooq...) |
| GET | /dictionaries/country-code/ | Страны (id + код) |

|-------|----------|-----------|
| POST | /repertoire/release | Создать релиз → возвращает id |

| GET | /repertoire/release/{id} | Получить инфо о релизе |

## ПОЛНЫЙ WORKFLOW: СОЗДАНИЕ РЕЛИЗА → ОТПРАВКА → СТАТИСТИКА

```
1. AUTH
   POST /auth/login { email, password }
   → access_token, refresh_token
   → сохраняем, используем во ВСЕХ запросах как X-Access-Token

2. DICTIONARIES (кэшируем в БД при первом запуске)
   GET /dictionaries/genres?object_type=music
   GET /dictionaries/release-types?category=audio&language=ru
   GET /dictionaries/outlets
   GET /dictionaries/languages
   GET /dictionaries/country-code/

3. ARTIST SYNC (если артист ещё не отправлен в Broma16)
   GET /account/{accountId}/artist/searche?searche=ArtistName
   → если найден → берём artist_id
   → если нет → POST /account/{accountId}/artist/ { name }
   → сохраняем broma16_artist_id в нашей БД

4. CREATE RELEASE
   POST /repertoire/release {
     title: "Track Name",
     subtitle: "version",
     release_type_id: 51,         // 51=Сингл, 2=Альбом, etc.
     performers: ["artist-uuid"], // из шага 3
     genres: ["Pop"],             // из словаря
     account_id: 2904,            // из /user/
     p_line: "2024 Label",
     c_line: "2024 Label",
     date_p_line: 2024,
     date_c_line: 2024,
     ean: "...", или generate_ean: true,
     catalog_number: "..." или generate_catalog_number: true
   }
   → получаем releaseId

5. UPLOAD RECORDINGS (для каждого трека по порядку)
   POST /repertoire/release/{releaseId}/recording/upload
   (multipart: file=WAV/FLAC, sort=1)
   → получаем recordingId

6. UPDATE RECORDING METADATA (для каждого трека)
   PUT /repertoire/release/{releaseId}/recording/{recordingId} {
     title: "Track Name",
     subtitle: "",
     genres: ["Pop"],
     isrc: "TJXXX2400001",
     main_performer: ["artist-uuid"],
     featured_artist: [],
     created_country_id: 186,  // Таджикистан
     created_date: "2024-06-15"
   }

7. ADD COMPOSITION + AUTHORS (ОБЯЗАТЕЛЬНО для модерации!)
   POST /repertoire/release/{releaseId}/recording/{recordingId}/composition
   → получаем contributorId

   Затем добавляем авторов с долями:
   {
     contributors: [{
       title: "Author Name",
       ownership: "50.00",
       publisher: "Publisher Name",
       publisher_share: "50.00",
       roles: ["C", "A"],    // C=Composer, A=Author, CA=Both
       controlled_by_submitter: 1
     }]
   }
   ⚠️ СУММА ДОЛЕЙ = 100% (ОБЯЗАТЕЛЬНО!)
   ⚠️ Минимум 1 контрибьютор с ролью C/A/CA

8. ADD LYRICS (опционально)
   PUT /repertoire/release/{releaseId}/recording/{recordingId}/lyrics
   { parental_warning_type: "not_explicit", is_instrumental: false,
     lyrics: "...", language: 1 }

9. UPLOAD COVER
   POST /repertoire/release/{releaseId}/cover/upload
   (multipart: file=JPG/PNG)

10. SET DISTRIBUTION (выбор площадок!)
    POST /repertoire/release/{releaseId}/distribution
    {
      distribution_outlets: ["spotify", "apple", "yandex", "vk", ...],
      sale_start_date: "2024-07-01"
    }

11. SEND TO MODERATION
    POST /repertoire/release/{releaseId}/send-moderate
    → релиз уходит в Broma16 на проверку (1-3 дня)
    → после модерации появляется в репертуаре и идёт на площадки

12. GET STATISTICS (периодически, cron-задача)
    POST /stat/v1/statistics/accounts/{accountId}/report
    { dateFrom: "2024-06-01", dateTo: "2024-06-30",
      outlets: "[spotify,apple,yandex]" }
    → получаем reportId

    Poll (каждые 30 сек):
    GET /stat/v1/statistics/accounts/{accountId}/report/{reportId}
    → когда status: "done" → output_file содержит URL
    → скачиваем файл → парсим → записываем в usage_reports
```

## КРИТЕРИИ ГОТОВНОСТИ РЕЛИЗА (Broma16 возвращает 422 если не выполнено)

- account_id указан и есть права управления
- Количество треков > 0
- У релиза есть обложка
- У всех треков есть аудио
- У всех треков есть произведения (composition)
- У всех произведений ≥ 1 контрибьютора
- У всех контрибьюторов указаны роли и доли
- Минимум 1 контрибьютор с ролью C/A/CA
- Сумма долей = 100%
- Тип родительского релиза не конфликтует с дочерними
- Для Сингла: название трека = названию релиза
