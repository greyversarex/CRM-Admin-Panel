ВАЖНОЕ ИЗМЕНЕНИЕ ПОДХОДА К ACRCLOUD
Текущая реализация ACRCloud (connectors/acrcloud.ts — Identify API, 512KB сэмпл, HMAC-SHA1)
— это НЕПРАВИЛЬНЫЙ подход для нашей задачи.

ACRCloud работает с нами по партнёрскому соглашению через S3 Drops.
Мы НЕ отправляем сэмпл через API. Мы загружаем полный DDEX ERN пакет (XML + аудио + обложка)
в их S3 бакет. Это как отправка релиза на DSP — только получатель ACRCloud.

ВЕРСИЯ DDEX — ВАЖНОЕ УТОЧНЕНИЕ
Менеджеры ACRCloud подтвердили: они принимают ЛЮБУЮ версию DDEX (3.8.2, 4.2, 4.3 и т.д.).

У нас в коде УЖЕ ЕСТЬ рабочий генератор DDEX ERN 4.3 (для доставки на DSP).
ПРИОРИТЕТ — переиспользовать существующий генератор ERN 4.3, а не писать новый под 3.8.2.

Алгоритм действий:

ПОСМОТРИ существующий генератор ERN 4.3 (тот, что используется для DDEX/SFTP доставки)
Адаптируй его для ACRCloud как получателя:
MessageRecipient PartyId: PADPIDA2016110503N
MessageRecipient Name: ACRCloud
MessageSender PartyId: PA-DPIDA-2024053004-T
MessageSender Name: Tajik Music
Проверь, что генерируется валидный XML в версии 4.3
Если существующий генератор легко адаптируется — ИСПОЛЬЗУЙ ЕГО, не пиши новый
Если существующий генератор 4.3 не подходит по структуре — тогда используй шаблон
ern/382 из раздела ниже как fallback (3.8.2 — это версия из sample.xml, точно рабочая)
В sample.xml (ern/382) показана структура, которую ACRCloud ТОЧНО принимает.
Если 4.3 пройдёт — отлично. Если нет — откатывайся на структуру 3.8.2.

ФОРМАТ DDEX ERN 3.8.2 (ИЗ SAMPLE.XML)
Вот точная структура XML, которую нужно генерировать.
Каждый релиз = один XML файл + аудио + обложка, упакованные в ZIP.

СТРУКТУРА ZIP ПАКЕТА
text

{UPC}.zip
├── {UPC}.xml                    ← DDEX ERN сообщение
└── resources/
    ├── {UPC}_T1_0_SoundRecording_001_001.wav   ← аудио трек 1
    ├── {UPC}_T2_0_SoundRecording_001_002.wav   ← аудио трек 2 (если есть)
    └── {UPC}_T3_Image.jpg                      ← обложка
XML СТРУКТУРА (генерировать ТОЧНО по этому шаблону)

  <MessageHeader>

    <MessageSender>

    <SentOnBehalfOf>
      <PartyId>PA-DPIDA-2024053004-T</PartyId>
      <PartyName>

      </PartyName>
    </SentOnBehalfOf>
    <MessageRecipient>
      <PartyId>PADPIDA2016110503N</PartyId>
      <PartyName>
        <FullName>ACRCloud</FullName>
      </PartyName>
    </MessageRecipient>
    <MessageCreatedDateTime>{ISO datetime}</MessageCreatedDateTime>
    <MessageControlType>LiveMessage</MessageControlType>
  </MessageHeader>

  <UpdateIndicator>OriginalMessage</UpdateIndicator>

  <!-- RESOURCE LIST -->
  <ResourceList>
    <!-- Для каждого трека — один SoundRecording блок -->
    <SoundRecording>
      <SoundRecordingType>MusicalWorkSoundRecording</SoundRecordingType>
      <SoundRecordingId>
        <ISRC>{ISRC трека}</ISRC>
        <ProprietaryId Namespace="PA-DPIDA-2024053004-T">{внутренний ID}</ProprietaryId>
      </SoundRecordingId>
      <ResourceReference>A1</ResourceReference>  <!-- A1, A2, A3... -->
      <ReferenceTitle>
        <TitleText>{название трека}</TitleText>

          <SubTitle>{версия}</SubTitle>
        </Title>
        <DisplayArtist SequenceNumber="1">
          <PartyName LanguageAndScriptCode="en">
            <FullName>{имя артиста}</FullName>
          </PartyName>
          <PartyId Namespace="PA-DPIDA-2024053004-T">{ID артиста}</PartyId>
          <ArtistRole>MainArtist</ArtistRole>
        </DisplayArtist>
        <!-- Featured артисты (если есть) -->
        <DisplayArtistName LanguageAndScriptCode="en">{имя артиста}</DisplayArtistName>
        <LabelName LanguageAndScriptCode="en">{название лейбла}</LabelName>
        <PLine>
          <Year>{год}</Year>
          <PLineText>{P-Line текст}</PLineText>
        </PLine>
        <Genre>
          <GenreText>{жанр}</GenreText>
          <SubGenre>{поджанр или убрать}</SubGenre>
        </Genre>
        <ParentalWarningType>{NotExplicit или Explicit}</ParentalWarningType>
        <TechnicalSoundRecordingDetails>
          <TechnicalResourceDetailsReference>T1_0</TechnicalResourceDetailsReference>
          <AudioCodecType>{WAV или FLAC}</AudioCodecType>
          <NumberOfChannels>2</NumberOfChannels>
          <SamplingRate UnitOfMeasure="kHz">44.1</SamplingRate>
          <BitsPerSample>16</BitsPerSample>
          <IsPreview>false</IsPreview>
          <PreviewDetails>
            <StartPoint>0</StartPoint>

            <ExpressionType>Instructive</ExpressionType>
          </PreviewDetails>
          <File>
            <FileName>{UPC}_T1_0_SoundRecording_001_001.wav</FileName>
            <FilePath>resources/</FilePath>
            <HashSum>
              <HashSum>{MD5 хэш файла}</HashSum>

        </TechnicalSoundRecordingDetails>
      </SoundRecordingDetailsByTerritory>

    </SoundRecording>

    <!-- COVER IMAGE -->

      <ImageType>FrontCoverImage</ImageType>
      <ImageId>
        <ProprietaryId Namespace="PA-DPIDA-2024053004-T">{ID}</ProprietaryId>
      </ImageId>

      <ReleaseReference>R0</ReleaseReference>

ЭТО НУЖНО РЕАЛИЗОВАТЬ — 4 МОДУЛЯ
МОДУЛЬ 1: DDEX ERN 3.8.2 ГЕНЕРАТОР
Создай server/connectors/acrcloud-ddex-generator.ts:

Метод generateErn382Xml(releaseId):

Берёт релиз из нашей БД (releases + tracks + artist + label)
Генерирует DDEX ERN 3.8.2 XML по структуре выше
КЛЮЧЕВЫЕ ПРАВИЛА:
Namespace: http://ddex.net/xml/ern/382 (НЕ 43!)
MessageSchemaVersionId: ern/382 (НЕ ern/43!)
xsi:schemaLocation: http://ddex.net/xml/ern/382 http://ddex.net/xml/ern/382/release-notification.xsd
MessageSender PartyId: PA-DPIDA-2024053004-T
MessageRecipient PartyId: PADPIDA2016110503N
Duration в формате ISO 8601: PT3M45S (3 мин 45 сек). Конвертировать из секунд.
Каждый аудиофайл: вычислить MD5 хэш
Обложка: вычислить MD5 хэш
ResourceReference: A1, A2, ... для треков, A{N+1} для обложки
TechnicalResourceDetailsReference: T1_0, T2_0, ... для треков, T{N+1} для обложки
FilePath: всегда resources/
FileName: {UPC}_T{n}_0_SoundRecording_001_{nn}.wav для аудио
FileName: {UPC}_T{n}_Image.jpg для обложки
Возвращает готовую XML строку
ВАЖНО: посмотри на существующий DDEX генератор (ern/43) — там есть полезная логика
(вычисление длительности, MD5, структура ResourceGroup). Адаптируй под 3.8.2.

МОДУЛЬ 2: ZIP УПАКОВЩИК
Создай server/connectors/acrcloud-packager.ts:

Создаёт ZIP архив со структурой:
text

Используй archiver или adm-zip npm пакет.

ЧЕГО НЕ ДЕЛАТЬ
НЕ используй Identify API (HMAC-SHA1, 512KB сэмпл) — это неправильный подход
НЕ используй ern/43 или ern/42 — только ern/382
НЕ отправляй файлы напрямую на DSP через этот генератор — это только для ACRCloud
Существующий ern/43 генератор НЕ ТРОГАЙ — он может пригодиться позже
КОНТЕКСТ: ПОЧЕМУ ИМЕННО S3 DROPS
ACRCloud — это наш партнёр по защите контента. Они проверяют треки на дубликаты
через фингерпринтинг. Но они НЕ работают через REST API для этого. Они принимают
релизы как "DSP" — через DDEX ERN пакеты, загруженные в их S3 бакет.

Процесс:

Мы создаём DDEX ERN XML (как если бы отправляли релиз на DSP)
Упаковываем с аудио в ZIP
Грузим в S3 бакет acrcloud-partners под префикс TajikMusic/
ACRCloud находит файл, фингерпринтит треки, проверяет дубликаты
Результат приходит позже (пока вручную от Tony Li, потом автоматизируем)
Это та же технология, которую используют FUGA, Symphonic, Revelator для работы с ACRCloud.
