# API Broma16 (ROD) — справочные материалы

`rod-api.openapi.json` — партнёрская спецификация ROD API, 57 методов.
Извлечена 19.08.2026 из <https://broma16.com/partner-api/partner-api.ru.html>
(страница ReDoc со встроенной спецификацией). Ссылку дала Вероника Бунина,
разработчик Broma16; поиском документация не находится.

Держим копию в репозитории, потому что на странице спецификация зашита в
JavaScript и по URL машинно не читается, а сверяться с ней приходится
постоянно.

## Что важно знать по ней

**Доли авторов** передаются методом
`POST /repertoire/release/{releaseId}/recording/{recordingId}/composition`:
у каждого автора `ownership` (процент), `publisher` с `publisher_share`,
`roles` из набора A (слова), C (музыка), CA (слова и музыка), AR (аранжировка),
AD (адаптация), TR (перевод) и `controlled_by_submitter`. У произведения должен
быть хотя бы один автор слов или музыки. По словам Вероники, шаг обязателен при
создании черновика.

**Авторские общества** — отдельный раздел: список обществ отдаёт
`GET /accounts/societies`, привязка автора к обществу делается по
релизу/фонограмме/автору с указанием территорий.

**Черновики** удаляются через
`DELETE /assets/draft/{composition|release}/{draftId}/remove`.

**Рингтоны и TikTok** заводятся отдельным методом
`POST /repertoire/release/additional/` — обычному релизу эти витрины
недоступны.

**Причины отказа модерации** лежат вне открытого API (Вероника прислала
отдельно): `GET /accounts/{accountId}/releases/{heaven11_release_id}/moderation`
и `.../notices?crucial=false&language=ru`. Обратите внимание: идентификатор
здесь heaven11, а не тот, что мы храним в `broma16_release_id`.

**Takedown через API не поддерживается** — только через интерфейс кабинета.
